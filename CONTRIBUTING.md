# Contributing to Free for Creators

Thanks for helping keep this list useful! There are two golden rules:

1. **Edit `data/*.json`, never `README.md`** — the README is generated by `scripts/build_readme.py` and CI rejects drift.
2. **Verify the license yourself** before submitting. "Free" must mean free for the stated use (see the criteria below).

## Adding a resource

You can either open an issue with the [Suggest a resource](../../issues/new/choose) template (no git needed), or send a PR:

1. Pick the right category file in [`data/`](../data). New category? Add it to `CATEGORY_ORDER` in `scripts/build_readme.py` too.
2. Append an entry object (fields below). Keep entries in a sensible order.
3. Regenerate the README:

   ```bash
   python3 scripts/build_readme.py
   ```

4. Commit the JSON **and** the regenerated README, then open a PR. CI validates schema and README sync.

## Inclusion criteria

A resource belongs here when **all** of these hold:

- **Legally free** for at least some real creator use (commercial or clearly-marked non-commercial) — no pirated packs, no "free download" mirrors of paid products, no cracked assets.
- **The license is discoverable** on the site. If you cannot find terms, it does not go in the list.
- **Directly useful to creators**: assets, media, templates — not tools/services that merely touch media (those belong in sister lists like `free-for-dev`).
- **Stable URL**: link to the canonical landing page, no affiliate links, no tracking parameters, no URL shorteners.
- **Not a duplicate** of an existing entry (URLs are checked globally by CI).

Borderline AI-generated asset sites: include only when the site states an explicit license for its outputs.

## Entry schema

Authoritative validation: `scripts/build_readme.py`; editor schema: `schema/entry.schema.json`.

| Field | Required | Values | Meaning |
| --- | --- | --- | --- |
| `name` | ✅ | string | Resource name |
| `url` | ✅ | `https://…` | Canonical landing page |
| `description` | ✅ | ≤160 chars, no `\|` | One-line "what is it" |
| `license` | ✅ | string | e.g. `CC0`, `Pixabay Content License`, `Various (per item)` |
| `attribution` | ✅ | `required` / `not-required` / `varies` | Must you credit the author? |
| `monetization` | ✅ | `allowed` / `conditional` / `varies` / `not-allowed` | Safe in monetized content? |
| `signup` | optional | `required` / `not-required` / `optional` / `unknown` | Account needed to download? |
| `notes` | optional | string | Caveats: free-tier caps, platform restrictions, … |
| `skip_linkcheck` | optional | boolean | Only for login-walled URLs; justify in the PR |

Semantics we use consistently:

- `monetization: conditional` — free commercial use **only under conditions** (credit link, free-tier caps, specific platforms like YouTube/Twitch). Put the condition in `notes`.
- `monetization: varies` — the site hosts mixed per-item licenses (marketplaces, CC aggregators).
- `attribution: varies` — some items need credit, some don't.

## Fixing problems

- **Dead link / license changed**: use the [Report a dead link](../../issues/new/choose) template or send a PR updating the entry.
- **Running the link checker locally**:

  ```bash
  python3 scripts/linkcheck.py             # everything
  python3 scripts/linkcheck.py --slug fonts  # one category
  ```

  CI runs it every Monday. Links returning 403/429 etc. are reported as *blocked* (bot walls, manual check) and do not fail the build; 404/DNS failures do.

## Style

- Descriptions in English, imperative-free, no marketing fluff ("amazing", "best").
- One fact per entry; if a site has a separate free section, link **to the free section** (e.g. `motionarray.com` free browse, not the homepage) when such a URL exists.
- Prefer the resource's own domain over aggregators, except for aggregator-type entries (search engines).

That's it — thanks for making creators' lives safer, one license column at a time. 🎨
